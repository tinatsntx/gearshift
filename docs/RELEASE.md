# Gearshift 0.3 release evidence

Private preview only. Public repository publication and directory submission are subsequent actions.

Live acceptance uses at most six Decisions requests. `live-proof.json` records the bounded calls, measured latencies, usage and selected settings. Three calls succeeded: connection validation, a small lookup (Luna / low), and a more involved review (Sol / xhigh). An identical repeat was served from cache without a fourth call. The dedicated key is locally saved and Windows-encrypted. These synthetic tasks prove connection and selection, not quality or savings.

Native acceptance failed in the tested Windows installation. Gearshift's three hooks were reviewed and trusted through `/hooks`; the host reported command-hook exit code 1. The fresh native child used unset model/effort, `fork_turns: "none"`, and a harmless fixed message. Its runtime metadata reported Terra / high while the parent used Sol / high. No Gearshift pre-spawn event, Decisions selection, or replacement arguments were recorded. A later attempt reused an existing task name and created no child; it supplies no acceptance evidence. The automatic-routing milestone is stopped and the tested host is marked unsupported. All temporary settings were restored. Total actual Decisions requests remains three.

The PATH CLI is 0.160.0; the desktop runtime is 0.160.1. Catalogs must match the running host identity and be fresh. A catalog from another executable is insufficient.

Pending acceptance: resolving native hook execution and obtaining correlated child proof, GitHub OAuth credentials, registered Gearshift plugin identity, Render Blueprint sync and mounted ChatGPT/Codex panel checks. The companion was installed with the supported single plugin identity; interactive installation, startup after Windows sign-in and uninstall still need acceptance. Publication must not describe any pending gate as passed. Hosted deployment is deferred while the initial native milestone is blocked.

Capture the final source commit and package hashes in `dist/release.json` when packaging. Runtime verification must record the installed package and tested host version. Checkpoints are evidence of partial implementation, not a completed automatic-routing milestone.
